The director, and the three projects it draws on

Evolving Agents Labs is an open-source lab for agents that learn how a team works — and can show what they learned. The director keeps the team’s way of working as a memory of small, linked statements, plans by walking it, delegates each step to a frontier model or to local models, and learns from every task. lora-kernel serves small local models as trained specialists. agentvcs versions and merges the harness those models run in, and attributes each change in a result to the change that caused it. gene-evidence writes evidence reports on predicted genes in which every sentence cites its source. The idea they share: what an AI system answers, changes or reports should be traceable to what produced it. What is built and what is planned between them: how they connect.

director

Can an agent keep a team’s way of working as memory — and plan, delegate and learn by it, so that each lesson is checked before it is kept?

active · D0–D15 · P0 measured  A meta-agent in evolving-agents: walks the operational memory to plan, hands each step to Claude Code or to a local model, learns from each task and from where the user moves work.

Built: the loop and its local interface, learning sealed as agentvcs patches (measured). Not yet: its local lane through lora-kernel’s specialists; no write access by default.

Why it matters: the rules a team writes down are not the ones it follows under pressure. If it works, the way of working is recalled at the moment it applies, and every new lesson is a reviewed, reversible change instead of a line in a file nobody rereads.

lora-kernel

Can one small local model, given a trained specialist per job and a library of notes it has learned to navigate, do an organisation’s routine work — and hand the rest to a frontier model?

active · flagship  An operating layer for specialized local AI agents: one resident model, a LoRA per job, facts in notes a person can edit, a router that abstains.

Built: specialists that beat the bare base on their job, a router that serves no foreign text locally, edits answered without retraining — measured. Not yet: no installable package, no real traffic.

Why it matters: if it works, an organisation’s routine AI work is served from one small local GPU — private, cheap to run, its facts in notes a person can read and edit — and only the rest is sent to a frontier model. The saving is not measured yet.

agentvcs

When an agent’s harness changes while it runs, can every result still be traced to the change that caused it — and can two diverging harnesses be merged on the evidence?

active · Rust core v0.1  Version control for agent harnesses: every step stamped with the harness version that produced it, patches gated, blame per metric, and a three-way merge whose real conflicts go to Claude Code — its only LLM.

Built: the Rust core, CLI, MCP server and Python SDK; attribution on a real model (below). Not yet: no PyPI package; no real Claude Code merge session recorded in the repository.

Why it matters: harnesses now change while agents run — a prompt, a model, a router. If it works, you know which change moved which result, and two harnesses that diverged are merged on evidence rather than by guess. Attribution has run on one real model.

gene-evidence

Can every sentence of a report on a predicted gene be traced to the tool output it rests on?

prototype · stage 1  Auditable evidence reports for gene predictions the reference annotation does not have: an evidence graph of tool outputs, and a report that cites it in every sentence.

Built: stage 1, deterministic, no language model; a development run on rat. Not yet: a model that drafts the report. Known limitation: it explains a candidate; it does not pick which to validate first.

Why it matters: a wet-lab experiment on a candidate gene costs real money. If it works, every claim in the evidence report can be checked against its source before that money is spent. The checkable report is built; choosing what to test is not.

How they connect

What they share is one rule: a statement that does not cite its source does not ship. gene-evidence’s check-report fails a sentence whose citation does not resolve; lora-kernel’s endpoint withholds an answer whose citation fails the referee’s check.

connectionstatuswhat it is
director → agentvcsbuilt Every memory edit the director keeps is an agentvcs patch: proposed, gated (it lints clean and a person accepted it), applied; blame credits the learning patch with the gain it made.

director → lora-kernelnext — not built The local lane through lora-kernel’s specialists and router rather than a bare model.

gene-evidence → agentvcsnext — not built Each evidence run as an agentvcs run, so a database release or rule change is a patch and blame traces a change in the report to it. Today the versions are recorded in versions.json.

director

The director

Plan by the team’s memory; learn by gated patches.

The memory is a small wiki of the team’s practices: pages of atomic statements (when this situation, do this, because of that incident), each linking to the ones that apply next. An index names the situations where a walk starts. The director walks it before every plan and cites what it followed; after a task it proposes edits, and a person accepts or rejects them. Code: packages/director.

From the SystemAgent

The 2025 toolkit’s parts, each pinned to a measurement.

The Evolving Agents Toolkit had a SystemAgent, a smart memory, a library and a bus of agents, Firmware rules and an evolution loop — and three test functions in 18,680 lines. The director keeps each idea and changes how it works: the SystemAgent plans by walking the memory instead of running its own loop; smart memory becomes linked When / Do / Because statements; the library and the bus become lanes; Firmware becomes rules enforced in code; evolution becomes a gated, versioned lesson. Piece by piece: EVOLUTION.md.

One harness today, three next

The harness is rented, never built.

Measured

Against our own previous way of working, never a frontier model.

ran  Learning from tasks: held-out probes of lab-specific lessons from 0.0 to 0.781, the first suite re-checked at 0.964 (D2). Learning the lane: after one move, public-facing drafts went 0 / 6 → 6 / 6 to the frontier while internal text stayed local (D3).

Roadmap

Each step names its measurement before it is built, against the version it replaces; a flat result is published as flat. Order, not dates. The full table: ROADMAP.md.

  1. Built: plan by walking the memory (D0), the loop and its interface (D1), learn from a task (D2), learn where work runs (D3), an Accept guarded by D0 — paired against the current memory, and run live to keep a lesson taught from the interface (D4).
  2. Your own director in ten minutes — director.compile on your CLAUDE.md and memory. ran from a clean clone on a public instruction file, to a first plan citing it, in about a minute and a half; next, a stranger’s own CLAUDE.md on their machine.
  3. The local lane through lora-kernel — a specialist serves its domain on your machine, the rest abstains to the frontier. ran live: a tracker read served by the specialist with its tools, an abstention sent to the frontier; not yet reliable abstention outside the phrasing it was measured on.
  4. Cheaper walks — today about eleven times today’s session per plan; judged by D0 held within 0.03 at three times the cost or less.
  5. Inside Claude Code — the walk in the session you already use; judged by D0 run there. ran as a plugin: 0.929, the same as the director (P0).
  6. Managed harnesses — an anthropic-managed and an antigravity lane, the same memory and gate; judged by D0 through each within 0.03 of 0.929.
  7. A team’s memory — lessons shared and merged with their evidence; judged by two members’ lessons merged without losing either’s probes.
  8. Held-out from the future — cases from work done after the memory was compiled. Bring yours: a situation where your agent ignored a rule you had written down.

The flagship · lora-kernel · Apache 2.0

The LoRA is not the textbook. It is the specialist who knows how to use the library.

One GPU, one small resident model, and a shelf of QLoRA adapters — each an expert defined by its corpus. An OpenAI-compatible API serves each request with the matching expert and sends everything else to a frontier model. Facts live in short notes a person can read and correct; the adapter holds the habit of navigating them.

  • A reasoning expert served the way its corpus taught it: 90/90, against 11/90 through tool_calls (79 : 0 paired). Same adapter, same cases.
  • Trained on walks over real regulations, it cites on a family it never saw: 18/23 against the untrained base’s 9/23.
  • A number edited in the notes after training: 17/17 rows answer the new value, 0 stale.
  • The default router serves foreign text locally 0/600 times, against the keyword dictionary’s 294/600.
  • Inbox triage on a new base: 471/475, a tie with its earlier release.

The second project · agentvcs · Apache 2.0

agentvcs

Change your harness while it runs and still know what worked.

Every step of a run is stamped with the harness version that produced it, so a patch applied mid-run can be gated, attributed with blame, rolled back or resumed from a checkpoint. Diverged harnesses merge dimension by dimension; each real conflict goes, with its evidence, to Claude Code, agentvcs’s only LLM, and the resolution is checked before it is recorded.

Repository → The July 2026 write-up (earlier Python version)

Measured, and not

A Rust core, CLI, MCP server, Python SDK and a conformance suite.

ran  On Qwen2.5-1.5B on llama.cpp, a patch applied mid-run passed a paired gate with a recall gain of +0.444, and blame attributed +0.442 to exactly one patch — the one applied (RUN_REAL.md).

ran  bisect re-executes each candidate from the run’s checkpoint: on a toy run where a regression landed next to a harmless patch, blame could only credit the pair; bisect named the regression (toy pipeline).

not built  No PyPI package; no real Claude Code merge session recorded; no remotes or sync.

The newest project · gene-evidence · Apache 2.0

gene-evidence

Auditable evidence for gene predictions the reference annotation does not have.

Some predicted genes are absent from the species’ reference annotation: missed genes, or artefacts. For each, gene-evidence analyze builds an evidence graph — locus context, retrocopy signature, Swiss-Prot homology, Pfam domains, ORF sanity — each node one tool output with its version and parameters. The report cites nodes in every sentence and check-report fails if one does not. No language model; the rules are in EVIDENCE.md.

Repository → The rat run

The first run, on rat

A development run, not a test of ranking quality.

947 candidates; 578 of 947 (61 %) sit on loci the reference calls pseudogenes, which is why locus context is read before homology. Two runs gave byte-identical graph and report, and every sentence passed the citation check; 35 unit tests. The top 100 are all tier 1 and repeat-rich families fill them, as written down before the run: 32 hit the Smok kinase family, 24 T-cell receptor or immunoglobulin variable segments, 2 retroviral Pol polyproteins (rank 1 among them).

known limitation  On plant genomes, against long-read transcript evidence, the tiers ranked supported candidates worse than the predictor’s own confidence score. Use the report to explain a candidate, not to choose which to validate first (README).
